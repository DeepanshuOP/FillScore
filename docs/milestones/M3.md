# M3 — Cost against expectation, and the AI layer's quality

Plan: `docs/superpowers/plans/2026-11-12-m3-cost-and-ai-quality.md`. Research notes: `docs/research/LOG.md` §M, §O, §P, §Q, §R. Decisions: ADR-0014, ADR-0015.

## What a user gets

- **Evidence rule that the prompt and the eval share.** The measure `evidence_cited` failed on every recorded run because the golden sets required keys that the prompt never asked for. One rule (`agents/required_evidence.py`) now feeds both. Its first meaningful number needs the new recordings (item 10).
- **Honest packets for rebuilt data.** A value that was not measured is absent from the prompt, and the measured order shortfall takes its place. Golden set v3 holds these packets.
- **Cost against expectation.** Each market order has an expected cost: what taker events of the same size cost in the same market hour (square-root model, calibrated on January 2024 public prints), with a 90% interval or "insufficient data". The v2 panel shows one line beside the letter: what the account's market orders cost against that benchmark, with its interval. The letter compresses near the top (94.35, 93.41, 93.68); this line compares the account with a market benchmark instead of with a fixed scale. Whether it separates real accounts is not yet tested: no real trades exist.
- **Quick and Deep.** The dashboard's Council panel runs a Quick audit (one model call) by default. A Deep audit (the 9-call Council) is opt-in. Both use the same grounding, verification and claim check, and the same budget (Deep 9 units, Quick 1). A refused Deep audit says whether Quick is still allowed and offers it.
- **A PDF report that matches the data.** A rebuilt demo's PDF prints the v2.3.0 components, the shortfall totals and the order outcomes; the v1 grade is labelled as the published grade of the earlier demo data.
- **A stricter claim check.** It now names a bare "because" and four other causal words, covers the specialists' own text, and reads look-alike dashes. It has its own version, so old recordings keep their rule.

## What changed in the plan, and why

- **`MEASURE_VERSION` stays 1.0.0** (the plan said 1.1.0). A bump makes the job re-measure every stored fill; `expectedCost` has its own version (`ec1.0.0`) and calibration file. ADR-0015.
- **No residual model yet.** The plan adds one only if it lowers the held-out error by 10%. That needs scikit-learn (free, not installed); the comparison was not run. Open.
- **Almgren et al. 2005 is not cited.** Its PDF answered 403. The two readable papers carry the model's shape; the multiplier Y is fitted here, because the papers use daily sigma and volume.
- **API default of `mode` is Deep, the dashboard default is Quick.** The evals and scripts that call the endpoint without a mode keep their behaviour; the product default is Quick because the dashboard always sends the mode.
- **Real accounts read "insufficient data" for cost vs expected.** The measurement job fetches at most 30 minutes of prints; the hour before an order needs a source (a REST kline request per order is the candidate; its endpoint must be read and cited first).
- **Claim rules got their own version and the claim check was widened** after the first re-record showed that it did not cover specialist text (LOG §R).
- **Packet order fix** (`executedAt`, then `_id`): the demo Council cache would otherwise have broken silently (LOG §R).

## Review

Independent `reviewer` subagent on the diff since `575e200`. No high finding. It confirmed that the v2.3.0 grades and hashes are unchanged, that the citations match the two papers, that `GET /ml/agents/council/budget` and the cache are isolated per account, and that the Quick path uses the same grounding, verification and claim check. Four medium and five low findings, all fixed with tests (red first):

| # | Finding | Fix |
|---|---|---|
| 1 medium | The specialist claim check skipped the flags of liquidity, alpha and fee (shown on the cards). | `enforce_specialists` checks every verdict's flags; one test per agent. |
| 2 medium | A degraded Deep run skipped the specialist check and recorded no redactions. | The check runs on every returned verdict; test with a failed risk auditor. |
| 3 medium | The cache key had no claim rules version, so a run made under 1.0.0 could be served for up to 7 days. | `claim_rules_version` is in the cache query and stored on every saved run; an unstamped run never matches. Test with a stored run of each kind (the first version of that test passed for the wrong reason, a different account id, and was corrected before the fix). |
| 4 medium | The copy overstated the benchmark ("cost of taker events in that hour") and the interval reads like the conformal one. | The line says "the modelled cost of a taker event of the same size in the hour before the order (fitted on January 2024)" and "a bootstrap over orders that leaves out the model's own error". The exception finding and the replay say "for one event". |
| 5 low | An order with no record read "resting orders are outside it". | Reason "order type unknown". |
| 6 low | A partly filled market order was averaged in with a cost over its intended notional. | Orders with fill ratio under 1 are left out and counted (`excluded.partlyFilled`). The demo values were rebuilt. |
| 7 low | The lower bound of the interval had no plus sign. | Both bounds use the signed format; test. |
| 8 low | "One model call" for Quick, though a replay check can add a call. | "Usually one model call"; the label shows the calls actually made. The budget still charges 1 unit (a re-reason is rare; noted). |
| 9 low | ARCHITECTURE.md lacked the budget route; the ADR said Y "between 0.10 and 0.40" (BNBUSDT is 0.0965). | Fixed. |
